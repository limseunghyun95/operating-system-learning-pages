Operating System · Day 22 / 63 · Virtual Memory

virtual address, physical address, MMU, page table

한 줄 요약: CPU가 만든 virtual address는 MMU가 현재 process의 page table과 권한을 따라 PFN+offset의 physical address로 번역하며, 번역 불가가 곧바로 “메모리 부족”을 뜻하지는 않는다.

1. 초보자 용어 사전

virtual address (VA)program의 instruction과 pointer가 사용하는 주소. process마다 독립된 address space에서 해석된다.
physical address (PA)CPU memory transaction이 최종적으로 가리키는 physical memory 주소. application이 보통 직접 다루지 않는다.
MMUMemory Management Unit. CPU의 virtual address를 physical address로 번역하고 접근 권한을 검사하는 hardware다.
page / page framevirtual memory의 고정 크기 조각이 page, physical memory의 같은 크기 슬롯이 page frame이다.
page size한 page의 크기. 4KiB가 흔하지만 architecture와 kernel 설정에 따라 다르므로 sysconf(_SC_PAGESIZE)로 확인한다.
VPN / PFNVirtual Page Number와 Page Frame Number. 주소를 page size로 나눈 몫에 해당한다.
offsetpage 내부 위치. 번역 전후에도 같은 low bits를 유지한다.
page tableVPN을 PFN과 권한 비트로 연결하는 계층적 자료구조. kernel이 관리하고 MMU가 읽는다.
PTEPage Table Entry. PFN과 present, read/write, user, execute, accessed, dirty 같은 상태·권한을 담는 최하위 mapping entry다.
VMAVirtual Memory Area. Linux가 “이 주소 범위는 어떤 파일/anonymous memory이며 어떤 권한인가”를 기록한 범위 metadata다.
page faultMMU가 현재 translation/permission으로 접근을 완료할 수 없어 CPU가 kernel handler로 제어를 넘기는 exception이다.
RSS / VSZRSS는 현재 resident physical memory의 근사치, VSZ는 예약된 virtual address range의 크기다. 둘은 같은 지표가 아니다.

2. mental model: 호텔 주소와 실제 객실

application은 “12층 345호”라는 virtual address만 본다. 같은 호수라도 process라는 서로 다른 호텔에 속할 수 있다. MMU는 현재 호텔의 안내 장부(page table)를 따라 실제 건물의 객실(page frame)을 찾고, 숙박권한(PTE bits)을 확인한다.

  • 주소가 존재해도 아직 실제 객실이 배정되지 않았을 수 있다: lazy allocation.
  • 서로 다른 virtual page가 같은 frame을 공유할 수 있다: shared mapping.
  • 같은 숫자의 VA가 process마다 다른 frame을 가리킬 수 있다: isolation.
  • 장부에 범위는 있지만 권한이 없으면 kernel은 고칠 수 없고 SIGSEGV를 보낸다.

중요한 차이: VMA는 “이 방을 사용할 정책과 범위”, PTE는 “현재 이 virtual page가 어느 frame에 어떤 hardware 권한으로 연결됐는가”다.

5. CS·kernel·hardware deep dive

5.1 pointer 값은 physical location이 아니다

C의 pointer를 출력하면 보통 해당 process의 VA가 나온다. 그 숫자를 physical RAM offset으로 해석하면 안 된다. context switch 때 CPU가 사용하는 address-space root가 달라질 수 있어 같은 VA가 다른 process에서 다른 PFN을 가리킨다. 반대로 shared memory는 서로 다른 VA를 같은 PFN에 연결할 수 있다.

5.2 offset은 번역하지 않고 보존한다

page size가 2^n이면 VA의 low n bits는 page offset이고 나머지가 VPN이다. page table은 VPN 부분을 PFN으로 바꾸며 offset은 그대로 붙인다. 4KiB라면 n=12다. alignment, page boundary, 내부 단편화를 설명하는 출발점이 이 비트 분해다.

5.3 계층형 page table은 sparse address space 비용을 줄인다

64-bit VA 전체를 flat array로 만들면 대부분이 빈 entry인데도 막대한 메모리가 든다. 계층형 구조는 사용하지 않는 큰 범위를 upper-level entry 하나의 absent로 표현한다. Linux의 architecture-neutral 모델은 PGD→P4D→PUD→PMD→PTE 다섯 level이며 hardware가 적은 level만 쓰면 나머지를 folding한다.

5.4 Linux에서 VMA와 page table은 서로 다른 질문에 답한다

VMA는 address range, protection, file/anonymous backing, private/shared 정책을 기록한다. PTE는 page 단위의 현재 translation과 hardware bit를 기록한다. anonymous mmap 성공 직후 VMA가 생겨도 모든 page에 private frame/PTE가 즉시 생긴다고 단정할 수 없다. 첫 접근 fault에서 zero page 연결이나 frame allocation이 일어날 수 있다.

5.5 page table도 physical memory를 소비한다

“VA는 공짜”라는 말은 과장이다. 넓은 range를 예약만 하면 leaf PTE가 모두 생기지 않을 수 있지만, sparse하게 많은 page를 touch하면 data frame뿐 아니라 여러 level의 page-table page, reverse mapping과 kernel metadata가 필요하다. 운영에서는 VSZ·RSS와 함께 page-table memory를 본다.

5.6 PTE는 주소와 protection을 함께 운반한다

PTE format은 architecture-specific이지만 보통 PFN과 present, writable, user/supervisor, execute-disable, accessed, dirty 같은 bit를 담는다. 따라서 MMU는 번역과 보호를 같은 access path에서 수행한다. W^X는 한 mapping이 writable이면서 executable하지 않도록 관리하는 대표적 보안 원칙이다.

5.7 page fault는 exception이며 항상 오류는 아니다

valid VMA 안의 lazy allocation, swapped page, copy-on-write는 kernel이 PTE/frame을 준비한 뒤 faulting instruction을 재실행할 수 있는 정상 경로다. 주소가 VMA에 없거나 write를 read-only VMA에 시도하면 복구할 계약이 없어 SIGSEGV로 이어진다. SEGV_MAPERR는 mapping 없음, SEGV_ACCERR는 permission 위반을 구분한다.

5.8 각 process의 mm_struct가 translation context를 묶는다

Linux user process는 task_struct가 참조하는 mm_struct에 VMA 정보와 top-level page table(PGD)을 가진다. 같은 process의 thread는 보통 이 address space를 공유하므로 pointer를 공유할 수 있지만 synchronization 없이 데이터 접근이 안전해지는 것은 아니다.

5.9 “64-bit pointer = 64-bit VA 모두 사용”은 아니다

architecture와 paging mode가 실제 implemented address width를 정한다. x86-64의 4-level/5-level paging은 서로 다른 범위를 제공하며 Linux는 compatibility 때문에 5-level hardware에서도 높은 userspace 주소를 기본적으로 적극 할당하지 않는다. pointer의 사용하지 않는 high bit를 임의 tag로 쓰는 코드는 미래 주소 폭에서 깨질 수 있다.

5.10 PFN 관찰 제한도 security boundary다

Linux /proc/pid/pagemap은 mapping state를 제공하지만, 실제 PFN은 CAP_SYS_ADMIN이 없으면 최신 kernel에서 0으로 가려질 수 있다. PFN 정보가 Rowhammer 공격을 돕기 때문이다. 실무 도구가 PFN 0을 “physical frame 0”으로 오판하지 않게 권한과 kernel version을 기록해야 한다.

7. 실무 best practice

  • page size를 4096으로 hard-code하지 말고 runtime/architecture 계약을 확인한다.
  • mmap, mprotect, munmap의 주소·길이 alignment와 overflow를 먼저 검증한다.
  • 메모리 알람은 VSZ만 보지 말고 RSS/PSS, anonymous/file, dirty, page-table memory, fault rate를 함께 본다.
  • mapping permission은 최소 권한으로 시작하고 writable+executable 동시 허용을 피한다.
  • MAP_FIXED는 기존 mapping을 덮을 위험이 있어 소유 범위가 증명된 경우만 사용한다.
  • process 외부로 raw pointer를 ID처럼 전달하지 않는다. IPC에서는 offset/handle과 shared mapping protocol을 사용한다.
  • physical contiguity가 필요한 DMA/huge page 요구와 virtual contiguity를 구분한다.
  • pagemap/PFN 진단은 privilege, kernel version, security impact를 명시하고 운영 기본 경로로 의존하지 않는다.

9. 놓치기 쉬운 함정

  • mmap 성공 = RAM 즉시 확보: VMA 예약과 resident frame 할당은 다를 수 있다.
  • VA가 연속 = PA도 연속: page마다 흩어진 frame에 매핑할 수 있다.
  • 같은 pointer 숫자 = 같은 데이터: address-space context가 다르면 mapping도 다르다.
  • page fault = 장애: demand paging의 정상 minor fault일 수 있다.
  • segfault = RAM 부족: 보통 unmapped/permission 문제이며 OOM과 다르다.
  • PTE와 VMA를 같은 것으로 보기: policy range는 있어도 현재 leaf translation은 absent일 수 있다.
  • PFN 0을 그대로 믿기: 무권한 process에는 보안상 masking될 수 있다.
  • pointer high bit 재활용: 더 넓은 VA mode나 pointer tagging 규칙에서 충돌할 수 있다.

10. 30분 실습: VA 분해·fork isolation·permission fault

macOS/Linux에서 실행 가능한 C 실습이다. anonymous mapping의 page alignment를 확인하고, fork 뒤 같은 VA가 독립된 값을 가질 수 있음을 관찰하며, PROT_NONE 접근을 child process에 격리해 보호 위반 signal을 안전하게 확인한다. Linux는 SIGSEGV가 계약이고 macOS에서는 SIGBUS가 관찰될 수 있다.

set -eu
lab_dir="$(mktemp -d)"
trap 'rm -rf "$lab_dir"' EXIT

cat > "$lab_dir/vm_lab.c" <<'C'
#define _GNU_SOURCE
#include <sys/mman.h>
#include <sys/types.h>
#include <sys/wait.h>
#include <unistd.h>
#include <signal.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>

#ifndef MAP_ANONYMOUS
#define MAP_ANONYMOUS MAP_ANON
#endif

typedef struct { uintptr_t addr; int value; } report_t;
static void die(const char *what) { perror(what); exit(1); }

int main(void) {
  long ps = sysconf(_SC_PAGESIZE);
  if (ps <= 0 || (ps & (ps - 1)) != 0) return 2;
  unsigned char *p = mmap(NULL, (size_t)ps * 2, PROT_READ | PROT_WRITE,
                          MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
  if (p == MAP_FAILED) die("mmap");
  printf("page_size_power_of_two=1 mapped_offset=%lu\n",
         (unsigned long)((uintptr_t)p % (uintptr_t)ps));

  p[0] = 7;
  int fd[2]; if (pipe(fd) != 0) die("pipe");
  uintptr_t parent_va = (uintptr_t)p;
  pid_t child = fork(); if (child < 0) die("fork");
  if (child == 0) {
    close(fd[0]); p[0] = 99;
    report_t r = { (uintptr_t)p, p[0] };
    if (write(fd[1], &r, sizeof(r)) != (ssize_t)sizeof(r)) _Exit(3);
    _Exit(0);
  }
  close(fd[1]); report_t r;
  if (read(fd[0], &r, sizeof(r)) != (ssize_t)sizeof(r)) die("read");
  int status; if (waitpid(child, &status, 0) != child) die("waitpid");
  printf("fork_same_va=%d isolated_value=%d\n",
         r.addr == parent_va, r.value == 99 && p[0] == 7);

  unsigned char *guard = p + ps;
  if (mprotect(guard, (size_t)ps, PROT_NONE) != 0) die("mprotect");
  child = fork(); if (child < 0) die("fork");
  if (child == 0) {
    volatile unsigned char forbidden = *guard;
    (void)forbidden; _Exit(4);
  }
  if (waitpid(child, &status, 0) != child) die("waitpid");
  int protection_signal = WIFSIGNALED(status) &&
                          (WTERMSIG(status) == SIGSEGV || WTERMSIG(status) == SIGBUS);
  printf("permission_fault_signal=%d\n", protection_signal);

  const uintptr_t model_va = 0x12345, model_pfn = 0xabc, model_ps = 4096;
  uintptr_t vpn = model_va / model_ps, offset = model_va % model_ps;
  uintptr_t pa = model_pfn * model_ps + offset;
  printf("translation_model vpn=0x%lx offset=0x%lx pa=0x%lx\n",
         (unsigned long)vpn, (unsigned long)offset, (unsigned long)pa);
  if (munmap(p, (size_t)ps * 2) != 0) die("munmap");
  return 0;
}
C

cc -std=c11 -O2 "$lab_dir/vm_lab.c" -o "$lab_dir/vm_lab"
"$lab_dir/vm_lab"

기대 출력

page_size_power_of_two=1 mapped_offset=0
fork_same_va=1 isolated_value=1
permission_fault_signal=1
translation_model vpn=0x12 offset=0x345 pa=0xabc345
  1. 0~10분: 실제 page size와 mapping address의 offset=0을 확인하고 VA를 VPN+offset으로 손계산한다.
  2. 10~20분: fork child와 parent의 VA 숫자는 같지만 값이 분리되는 이유를 “address space, page table, COW preview”로 설명한다.
  3. 20~30분: Linux에서 별도 실행 중인 process의 /proc/PID/maps를 보고 VMA range와 permission을 표시한다. pagemap PFN은 root 권한으로 우회하지 말고 masking 가능성을 기록한다.

안전 장치: PROT_NONE 접근은 fork child에서만 수행하므로 parent 학습 shell은 살아남는다. 실제 service에서 SIGSEGV를 복구 수단처럼 잡아 계속 실행하지 말고 crash evidence를 보존하는 편이 안전하다.

11. 실패 시나리오: 1TiB VSZ를 memory leak으로 오진

allocator가 넓은 virtual arena를 PROT_NONE으로 예약해 VSZ가 1TiB가 됐다. 모니터가 VSZ 하나만 임계치로 사용해 장애로 선언했고 운영자가 process를 재시작했지만 RSS와 system memory pressure는 낮았다. 반대로 일부 worker가 arena 곳곳을 sparse touch하면서 page-table memory와 minor fault가 증가한 진짜 비용은 보지 못했다.

대응: VSZ, RSS/PSS, anonymous/file breakdown, page-table memory, fault rate, PSI를 함께 확인한다. 재발 방지: virtual reservation과 committed/resident 지표를 분리하고, VMA/PTE/frame이라는 세 층으로 runbook을 작성한다.

12. 대기업 면접 질문 3개

  1. “virtual address는 어떻게 physical address가 되나요?”
    답변 포인트: VA를 level index와 page offset으로 분해하고, MMU가 현재 address-space root에서 계층형 page table을 walk해 PTE의 PFN·permission을 얻는다. PA는 PFN+동일 offset이며 실패하면 page-fault exception으로 kernel에 진입한다.
  2. “두 process의 같은 pointer 값은 같은 메모리인가요?”
    답변 포인트: 기본적으로 아니다. process별 mm/page-table context가 다른 PFN으로 번역할 수 있다. shared mapping이면 같은 frame을 의도적으로 공유할 수 있고, 같은 process thread는 address space를 공유한다.
  3. “mmap 성공과 실제 RAM 사용의 차이는?”
    답변 포인트: mmap은 먼저 VMA와 virtual range 계약을 만들 수 있고 physical frame/PTE는 first touch에서 lazy allocation될 수 있다. VSZ와 RSS를 분리하고 fault, PSS, page-table overhead, overcommit 정책을 함께 본다.
